# Plan review 2 — external-agent-join (token-carried design)

**Verdict: NOT READY. Score: 58/100.** The token-carried pivot genuinely removes the v1 multi-field global-rebind race: the proposed member operations take a self-locating token and parameterize the inbox reader by explicit session/member values rather than mutating `IDENTITY` or `_session_id` (`docs/features/external-agent-join/plan.md:31-56`, `:285-290`). However, the v2 plan still has four correctness holes: the record-first crash reconciliation does not handle the stated `open ticket + existing record` state, the supposed shared guaranteed-delivery guard is reached only after delivery rows/claims have already been mutated, revocation is not specified to remain locked through inbox I/O, and token-based readers violate the current single-process cursor-writer assumption (`docs/features/external-agent-join/plan.md:204-221`, `:244-256`, `:276-280`; `src/claude_teams/server_simple.py:440-455`, `:2940-2969`, `:3997-4049`, `:4246-4308`). The bearer secret would also be exposed by `list_agents(full=True)`, because that tool splats every raw registry field into its result (`docs/features/external-agent-join/plan.md:161-166`; `src/claude_teams/server_simple.py:4660-4667`, `:4691-4703`). Before implementation, the plan must: (1) define open-ticket and post-ticket/pre-marker recovery precisely; (2) redact or avoid plaintext credentials in public raw-record views; (3) hold membership validation through each side effect and add a cross-process cursor lock; (4) put external-target checks before both `_open_delivery_record` and `_claim_delivery_record`/reconciliation, with an authoritative recheck; and (5) replace prompt-only ambient-tool containment with a technical isolation decision or explicitly make an isolated external-only endpoint/profile a release condition. The test matrix must be expanded accordingly.

## Blockers (must fix)

1. **Do not publish the bearer credential through `list_agents(full=True)`, and define credential-at-rest handling.**
   - The planned raw external row stores the member secret as `member_token` (`docs/features/external-agent-join/plan.md:159-166`). Full list currently returns `{**agent, ...}` and its contract explicitly says it restores the raw registry record (`src/claude_teams/server_simple.py:4660-4667`, `:4691-4703`). Any agent in the flat session can call this tool after its normal `AGENT_SESSION_ID` resolution, and an ambient same-cwd root can auto-adopt through `_active_session_id` (`src/claude_teams/server_simple.py:649-690`, `:763-859`, `:4660-4678`). Because the token embeds the session id, `session_id + member_token secret` reconstructs the full bearer credential (`docs/features/external-agent-join/plan.md:51-56`, `:161-166`). This is a tool-level disclosure, not merely the accepted “same user can read files” threat (`docs/features/external-agent-join/plan.md:44-49`).
   - **Concrete fix:** add a single public-record sanitizer used by every raw/full status surface and test that `member_token`, ticket token, token digests, and future credential fields never appear. Prefer storing a fixed-length digest and comparing fixed-type bytes with `hmac.compare_digest`; if response-loss idempotency requires reproducing the same token, derive it deterministically from the presented join token plus a protected server secret, or keep the reversible secret in a separate credential store that public registry views never merge. The `hmac.compare_digest` claim is currently only plan text and cannot be verified from repository code because `_resolve_member` does not yet exist (`docs/features/external-agent-join/plan.md:51-56`, `:204-217`). Add full-list/check/status leakage tests.

2. **Repair the two-file/marker reconciliation algorithm; the written record-first protocol is not idempotent.**
   - The plan says `open + unexpired` proceeds to insert, and only `used` reconciles an existing `join_ticket_id` (`docs/features/external-agent-join/plan.md:247-250`). It then claims a crash after saving the record but before saving the ticket will be reconciled (`docs/features/external-agent-join/plan.md:251-255`). Those statements conflict: the retry sees `open` and inserts again. The current registry save is a non-atomic overwrite, making precise retry behavior especially important (`src/claude_teams/server_simple.py:511-519`).
   - The plan also writes the marker after both stores but returns immediately on a `used + matching record` retry, so a crash at that point can leave a permanently missing joined marker (`docs/features/external-agent-join/plan.md:247-256`).
   - **Concrete fix:** under `_agents_file_lock`, first find a record by `join_ticket_id` for both `open` and `used` tickets. For `open + record`, validate exact immutable fields, mark the ticket used, save it, then ensure/repair the marker before returning. For `used + record`, also ensure/repair the marker before returning. Only `open + no record` may insert. Define error results for mismatched/duplicate `join_ticket_id` rows and whether marker-write failure is retriable. Add injected-failure tests for (a) agent-save failure, (b) record saved/ticket open, (c) ticket used/marker absent, and (d) response loss after marker. Keep the one-record invariant in every state (`docs/features/external-agent-join/plan.md:346-350`).

3. **Make membership validation and each side effect one linearizable operation; fix leave idempotency.**
   - `_resolve_member` promises validation under `_agents_file_lock`, but §2.4 does not state that the lock remains held through parent-inbox append or through the complete inbox cursor transaction (`docs/features/external-agent-join/plan.md:204-221`). Kill removes the row and performs cleanup while holding the registry transaction (`src/claude_teams/server_simple.py:4429-4510`). If an external call releases the registry lock first, a validated send can append after kill/leave, and a validated read can race inbox/cursor deletion.
   - `leave_team` cannot be both idempotent and implemented through a helper that rejects left records before tool dispatch (`docs/features/external-agent-join/plan.md:191`, `:213-217`, `:360`).
   - **Concrete fix:** specify a callback/transaction helper that acquires the agents lock, validates token/backend/status, and retains it through append/read/cursor-save/marker-write. Define one lock order (agents lock before inbox/cursor lock) and use it in kill, leave, send, and read. Give `leave_team` an `allow_left=True` lookup mode that returns `already_left` without any activity-marker rewrite. Add deterministic barriers for kill/leave racing `external_send` and `external_read`, not only lead-send racing kill (`docs/features/external-agent-join/plan.md:361-363`).

4. **Add cross-process cursor serialization for external readers.**
   - Current `_inbox_lock` is explicitly process-local and relies on one process owning one reader identity (`src/claude_teams/server_simple.py:440-455`). `read_messages` performs load/read/advance/save under only that lock (`src/claude_teams/server_simple.py:2551-2554`, `:2561-2629`). A bearer token is intentionally portable across MCP restarts and can be presented concurrently by an old and new server or by two holders, so that single-writer premise no longer holds (`docs/features/external-agent-join/plan.md:37-43`, `:371`). Two processes can both return the same unread message before either cursor save wins.
   - **Concrete fix:** add a per-session/per-reader cross-process cursor lock (or use a carefully ordered session lock) around the whole load/read/advance/save operation for external readers. Preserve the in-process lock for ambient reads if desired, but document lock ordering with the registry lock. Add a multiprocessing test proving exactly one destructive read receives a message, plus concurrent tests for `from_agent`/`since_seq`, `limit=0`, and different member tokens/readers (`src/claude_teams/server_simple.py:2494-2525`, `:2571-2655`).

5. **Replace the nonexistent “shared preparation boundary” with explicit pre-store guards on both delivery paths.**
   - `_guaranteed_delivery` receives an already durable row and says it never creates it (`src/claude_teams/server_simple.py:2940-2959`). `_guaranteed_send` calls `_open_delivery_record` before `_guaranteed_delivery` (`src/claude_teams/server_simple.py:4041-4049`, `:4068`), and `deliver_pending` calls `_claim_delivery_record` before `_guaranteed_delivery` (`src/claude_teams/server_simple.py:4284-4308`). The backend lookup at `_prepare` is therefore too late to satisfy the plan's byte-identical “before any claim/mutation” promise (`src/claude_teams/server_simple.py:2962-2972`, `:3018-3030`; `docs/features/external-agent-join/plan.md:276-280`, `:362`, `:376-380`).
   - **Concrete fix:** after existing key validation, add a read-only external-target preflight in `_guaranteed_send` before `_open_delivery_record`; in `deliver_pending`, identify/refuse external targets before reconciliation and before `_claim_delivery_record`. Retain an authoritative under-agents-lock check at `_prepare` before backend resolution or lease reservation to close target replacement races (`src/claude_teams/server_simple.py:2962-2995`, `:3169`). Tests must byte-compare `deliveries.json` and assert no active claim, attempts, lease, binding scan, or backend registry lookup in both direct and drain paths (`docs/features/external-agent-join/plan.md:362`). There is no single existing call site that can do all of this, so the plan should name the two early call sites plus the authoritative recheck.

6. **Prompt discipline alone is not adequate containment for ambient root tools.**
   - The plan admits the joined model can call plain tools as `team-lead` and relies on “use ONLY external_*” instructions (`docs/features/external-agent-join/plan.md:384-391`). Plain `send_message`, `read_messages`, `list_agents`, `kill_agent`, and status tools all derive authority/session from ambient globals (`src/claude_teams/server_simple.py:2412-2446`, `:2494-2553`, `:4411-4429`, `:4660-4678`, `:4754-4781`). Same-cwd adoption does exist today through candidate recovery, but “unchanged by this feature” is inaccurate: a `running` external row is non-terminal and can itself make/keep the lead session recoverable (`src/claude_teams/server_simple.py:649-704`; `docs/features/external-agent-join/plan.md:399-402`). The feature also deliberately places a manually started Desktop model in exactly the scenario where a wrong tool call triggers that path.
   - **Concrete fix:** investigate FastMCP request/client context and specify client-scoped tool filtering if it is reliable. If it is unavailable, use an external-only MCP endpoint/process/profile exposing only `join_team` and `external_*`, or require such isolation as a release gate. At minimum, the plan must stop calling shared-process correctness “eliminated,” state that ambient calls can spawn/kill/read as root, and add wrong-tool smoke tests. A prompt warning is useful defense-in-depth but cannot be the sole correctness control (`docs/features/external-agent-join/plan.md:37-49`, `:392-395`).

7. **Expand the red-test matrix before implementation.**
   - Add: public token-redaction tests for full/compact list, check, and status; subprocess restart with a real exact binding and same-cwd candidate while `_active_session_id`/recovery helpers are fail-fast; two-process `external_read`; full cursor compatibility (`from_agent`, `since_seq`, `full`, `limit`, `max_chars`, invalid combinations); open-ticket and post-ticket/pre-marker failure injection; spawn-then-ticket and concurrent spawn/ticket reservation; kill/leave races against both external directions; malformed token versions, extra separators, uppercase/noncanonical UUIDs, wrong secret lengths/non-ASCII, and corrupt stored token types; atomic marker replacement and marker-write failure semantics; and exact `join_prompt`/`instructions`/`watch_argv` contents (`docs/features/external-agent-join/plan.md:343-374`; `src/claude_teams/server_simple.py:2494-2658`; `src/claude_teams/hooks.py:63-68`; `src/claude_teams/server_simple.py:1096-1101`).
   - Test 12 should prove absence of reads/calls to all ambient recovery paths, not only unchanged outputs, and test 19 must retain the lead's binding/candidate so it actually proves precedence is bypassed (`docs/features/external-agent-join/plan.md:359`, `:371`; `src/claude_teams/server_simple.py:763-859`). Test 16 covers lead-send/kill only and does not prove token-call revocation linearizability (`docs/features/external-agent-join/plan.md:363`).

## Non-blocking findings

1. **Token grammar needs an exact contract.** Specify exactly three colon-delimited fields, version `wam1`, canonical lowercase hyphenated UUID text, and exactly 32 lowercase hex secret characters before calling `compare_digest`; reject non-string/corrupt stored values without raising. Current `resume_session` only calls `uuid.UUID(sid)` and checks direct-child location, which is path-safe but not a canonical token grammar (`docs/features/external-agent-join/plan.md:51-56`, `:209-217`; `src/claude_teams/server_simple.py:4535-4550`). Test 22 currently covers only a bad UUID, wrong secret, and deleted directory (`docs/features/external-agent-join/plan.md:374`).

2. **The “one-time ticket” wording is misleading under idempotent replay.** For at least the retention interval, anyone retaining the used join token can replay it and receive the member token again (`docs/features/external-agent-join/plan.md:148-153`, `:177-181`). That may be the correct response-loss tradeoff, but docstrings should call it a replayable recovery credential during retention rather than strictly one-time (`docs/features/external-agent-join/plan.md:315-319`).

3. **TTL parsing should not copy `_idle_seconds` literally.** `_idle_seconds` catches only `ValueError` and permits negative, zero, NaN, and infinity (`src/claude_teams/server_simple.py:253-263`). A ticket TTL parser should require a finite positive value and otherwise use 24 hours; add tests for `0`, negative, `nan`, `inf`, and malformed text (`docs/features/external-agent-join/plan.md:148-153`).

4. **Centralize external binding behavior.** The plan names `check_agent` and full list, but compact list also resolves a binding when no marker timestamp exists, and `agent_status` does so on its fallback (`src/claude_teams/server_simple.py:4624-4638`, `:4685-4702`, `:4716-4725`). Returning `BindingResult("not_applicable")` from the shared server wrapper for `backend == "external"` is less error-prone than scattered call-site branches (`src/claude_teams/server_simple.py:1232-1244`; `docs/features/external-agent-join/plan.md:305-313`).

5. **Define heartbeat failure semantics.** Cursor save and inbox append are user-visible side effects, while the activity marker is secondary liveness metadata (`docs/features/external-agent-join/plan.md:187-191`, `:285-290`). If atomic marker writing fails after a successful send/read, the tool should not falsely report that the message operation failed and invite a duplicate; return success with a heartbeat warning or define a safe retry contract. The atomic marker pattern itself is sound (`src/claude_teams/hooks.py:63-68`).

6. **Name reservation needs expiry semantics and both orderings.** “Open ticket names” should mean open **and unexpired**, otherwise retained expired rows reserve names for seven extra days (`docs/features/external-agent-join/plan.md:148-153`, `:235-242`). The shared agents lock can serialize ticket-then-spawn and spawn-then-ticket, but tests currently cover only ticket-then-spawn (`docs/features/external-agent-join/plan.md:343-345`).

7. **Join-prompt construction should be exact and injection-aware.** The test should assert literal session id/token values, the exact `external_send`/`external_read` names, “save member_token,” restart instructions, and `watch_argv --reader <actual-name>`; merely searching for three substrings will not catch swapped credentials or the wrong reader (`docs/features/external-agent-join/plan.md:197-202`, `:257-259`, `:343`, `:346`). `note` is lead-authored free text, so its placement/delimiters should be deterministic.
