1. **SHOULD — The Risks section still specifies the superseded, unsafe workspace-close rollback.** The revised design correctly keeps today's tab-only rollback and explains why Herdr's verified last-tab behavior makes it safe under either race ordering (`docs/features/herdr-workspace-per-repo/plan.md:45-47`, `docs/features/herdr-workspace-per-repo/plan.md:162-176`); test 12 likewise requires that no `workspace close` is issued (`docs/features/herdr-workspace-per-repo/plan.md:263-265`). However, the risk table still says rollback “closes a workspace this spawn created; never one it reused” (`docs/features/herdr-workspace-per-repo/plan.md:221`), and Files affected still names “`spawn_process` rollback” as a change (`docs/features/herdr-workspace-per-repo/plan.md:201-203`). Those instructions directly contradict the settled design and could reintroduce the destructive race during implementation. Change the risk mitigation to “rollback closes only the agent tab; Herdr removes the workspace iff it was the last tab,” and remove rollback from Files affected unless an actual rollback-code change is intended. The rollback reasoning itself has no remaining ownership hole: if another tab wins the race first the workspace survives; if the failed tab closes first, a racing targeted create receives `workspace_not_found` and follows the already specified guarded-create recovery.

2. **SHOULD — The lock path is not concretely session-namespaced despite claiming to be per-session.** The plan calls the lock per session and label and says its filename is exactly `ws-<sha256(label)[:16]>.lock` as a sibling of `_start_lock_path()` (`docs/features/herdr-workspace-per-repo/plan.md:148-156`). In the actual code, `_start_lock_path()` puts all session lock files in the same config root and achieves session separation by including `self._session` in the filename (`src/claude_teams/backends/process_manager.py:2683-2693`). A sibling named only from the label would therefore serialize identical labels across every Herdr session, contrary to the design; the statement that “the validated session name namespaces it” does not say where that namespace is encoded. Specify the complete path, for example `win-agent-teams-<session>.ws-<digest>.lock` (or a session-specific subdirectory), and extend test 12b so equal labels in different sessions produce different paths while equal label/session pairs produce the same path (`docs/features/herdr-workspace-per-repo/plan.md:266-268`).
