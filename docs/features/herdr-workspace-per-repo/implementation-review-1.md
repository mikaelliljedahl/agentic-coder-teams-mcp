1. **SHOULD — Non-`.git` common-directory names lose an arbitrary suffix instead of stripping only a terminal `.git`.** `_repo_name` uses `path.stem` for every common directory not literally named `.git` (`src/claude_teams/backends/process_manager.py:2797-2805`). That happens to produce `portal` for the tested conventional bare repo `portal.git`, but it also turns a valid bare repo/common dir named `portal.data` into `portal`. The approved rule is the directory's own basename with one terminal `.git` removed (`docs/features/herdr-workspace-per-repo/plan.md:55-62`). Use `path.name.removesuffix(".git")` (with the existing nonempty fallback) rather than `Path.stem`, and add a bare/common-dir case with a non-`.git` dotted basename; the current test covers only `/srv/git/portal.git` (`tests/test_backends/test_process_manager_herdr.py:1777-1784`).

2. **SHOULD — Undecodable Git output does not take the promised folder-name fallback.** The Git probe decodes with `errors="replace"` (`src/claude_teams/backends/process_manager.py:2820-2834`). Invalid path bytes therefore become printable U+FFFD characters, are accepted by `_sanitise_label`, and can produce a replacement-character workspace label rather than falling back. The approved plan explicitly classifies undecodable output as a failed probe (`docs/features/herdr-workspace-per-repo/plan.md:63-74`), but the fallback parametrization tests only nonzero exit, missing Git, timeout, and whitespace (`tests/test_backends/test_process_manager_herdr.py:1787-1803`). Decode strictly and catch `UnicodeDecodeError` (or otherwise detect replacement), then add an invalid-UTF-8 subprocess result test at the actual decode boundary.

3. **SHOULD — The concurrency test is timing-dependent and does not prove both spawns converge on the created workspace.** Its barrier is entered from `workspace create`, which is already inside the file lock (`tests/test_backends/test_process_manager_herdr.py:2150-2184`); with the correct implementation only one thread can reach it, so it necessarily times out after 0.2 seconds instead of proving both threads observed the initial absence. On a slow scheduler, an implementation with no lock can also time out, create once, and let the late thread observe the workspace, making the test pass vacuously. The test also neither records thread exceptions nor asserts the joined threads terminated (`tests/test_backends/test_process_manager_herdr.py:2189-2200`). Finally, the reused-tab stub returns fixed workspace `w3` even though the newly created workspace is `w1`, and the test asserts only `created == ["w1"]`, not that the second `tab create` carried `--workspace w1` (`tests/test_backends/test_process_manager_herdr.py:2164-2179`). Put a barrier on each thread's first/outside-lock list response, collect and re-raise thread failures, assert both threads terminate, and assert exactly one `workspace create` plus one targeted `tab create --workspace w1`.

4. **NIT — Session namespacing is implemented but not pinned by the lock-path test required by the plan.** `_workspace_lock_path` correctly includes both the validated session and a SHA-256 label digest (`src/claude_teams/backends/process_manager.py:2761-2773`). The test verifies containment, label differentiation, and same-label stability only in the default session (`tests/test_backends/test_process_manager_herdr.py:2203-2218`); it never constructs two managers with different `WIN_AGENT_TEAMS_HERDR_SESSION` values. Add the plan's assertion that the same label in two sessions yields different paths (`docs/features/herdr-workspace-per-repo/plan.md:269-271`).

5. **NIT — The sentinel's fresh-server fallback is a new branch with no direct test.** The sentinel test covers the common case where unqualified `tab create` succeeds (`tests/test_backends/test_process_manager_herdr.py:2274-2291`), while `_create_in_new_workspace(label=None)` and `_workspace_create(label=None)` are exercised only when that unqualified call returns a no-workspace code (`src/claude_teams/backends/process_manager.py:3246-3281`). Add a sentinel-plus-fresh-server case asserting there is still no `workspace list`, the fallback workspace keeps the legacy `worker@team` label rather than the repo label, and spawn succeeds. The current implementation appears correct; this closes a meaningful escape-hatch regression gap.

The core implementation otherwise matches the approved design: authoritative `EMPTY` goes through the guarded direct-create path; both outer and inner `UNKNOWN` use unqualified creation and retain `_HERDR_NO_WORKSPACE_CODES` recovery (`src/claude_teams/backends/process_manager.py:3214-3271`); workspace parsing is conservative and deterministic (`src/claude_teams/backends/process_manager.py:2843-2880`); rollback still closes only the returned tab (`src/claude_teams/backends/process_manager.py:3367-3376`); and repository routing changes are confined to `HerdrProcessManager`. Repository-wide searches show `_create_tab`, `_tab_create_args`, and `_write_provenance` have no external Python callers, while `_write_provenance` also retains defaults for its new parameters.

Overall verdict: **CHANGES REQUESTED**
