1. **BLOCKER — Readable tokens activate a false-death/resume path that the safety argument overlooks.** `plan.md:73-79` claims read failure cannot cause an unsafe reclaim and simply restores today's behavior. However, `src/claude_teams/backends/process_manager.py:439-447` returns dead on an unreadable current token when an expected token exists; with no expected token it instead checks PID liveness. The new reader changes persisted agent records from the latter case to the former (`src/claude_teams/server_simple.py:3353-3374,4114`). After restart, this helper is used by manager health checks (for example `process_manager.py:1935-1951`), and `_agent_alive` passes the stored token (`server_simple.py:1753-1756`). With a bound resumable session and no distinct sidecar, a transient read failure makes `alive=False` at `server_simple.py:4287`, skips the live/busy guard at `4357-4414`, and permits reservation and resume at `4426-4439,4551-4559`. The old process is not shut down because `plan.alive` is false. This can run two workers in the same conversation even though ownership_probe itself handles an unreadable current token conservatively. Cleanup also consumes this false-dead result (`server_simple.py:5924-5925`). **Fix:** before enabling persisted Darwin tokens, preserve unknown-vs-dead through the health/resume decision (or conservatively prevent resume/cleanup while a token is unreadable and the process may be live). Add a deterministic regression with an empty manager registry, stored valid token, live PID, injected read failure, bound session and no sidecar; assert no resume and no live-child artifact deletion. This prerequisite is independent of the deferred kill-verification redesign; revise the two-file scope or land the prerequisite separately first.

2. **SHOULD — Distinguish failed capture from failed re-read, and explicitly disposition inherited reclaim limitations.** `plan.md:40-44,73-79` compresses different cases. `process_manager.py:394-412` first accepts a live tracked child, then classifies a missing expected token as NOT_OURS *before* checking liveness. Both reservation and claim creation store an unchecked token (`server_simple.py:4434,4897`); an initial capture failure therefore produces a reclaimable live holder: `src/claude_teams/leases.py:250-257,288-291` and `server_simple.py:4874-4877`. Even an active same-process claim is rejected before the claim-ID check. This is pre-existing on macOS, not a regression introduced by successful reads, but it disproves universal fail-closed safety. Old tokenless records also remain tokenless after upgrade. Further, the manager's liveness predicate is not universally conservative on permission errors: the POSIX branch at `process_manager.py:898-901` treats all OSError as absent. **Fix:** replace the universal claim with a caller-specific account; explicitly record these pre-existing limitations and their disposition. Prefer refusing lease/claim acquisition when initial identity capture fails, with tests for capture failure, legacy tokenless records, later read failure, mismatch, matching token and dead PID. Do not backfill a legacy expected token from a possibly reused PID. If these policy changes remain separate, say so and do not claim all None results are safe.

ABI and r1 disposition:

- **r1 finding 4: decoding corrected, validation coverage only partly complete.** Offset zero and `<qi` are correct for the stated little-endian LP64 ABI: [Apple user64_kinfo_proc](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/sysctl.h#L1041-L1043) starts with kp_proc, [user64_extern_proc](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_internal.h#L638-L645) starts with the start-time union, and [user64_timeval](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/_types/_user64_timeval.h#L30-L34) has signed 64-bit seconds and signed 32-bit microseconds. Twelve bytes suffice to decode those fields; the 16-byte ABI object includes trailing padding, which must not enter the value. Positive seconds and `0 <= usec < 1000000` are reasonable sanity checks, not proof of a complete/recognized kinfo_proc layout. Nonzero-padding and independent native start-time checks are good additions (`plan.md:55-60,100-111`). Explicitly report native arm64 and x86_64 coverage separately; missing x86_64 execution must remain unverified, not implied by portable tests.
- The two-call pattern is appropriate. The [Apple sysctl declaration](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/sysctl.h#L1397-L1399) maps to `argtypes = [POINTER(c_int), c_uint, c_void_p, POINTER(c_size_t), c_void_p, c_size_t]`, `restype = c_int`. Query size with oldp=NULL, allocate capacity, pass it back as oldlen, then validate the actual output length. An error at either call returns None; disappearance between calls can produce zero output. No retry is necessary for the proposed conservative reader contract. The plan promises declarations but does not spell them out; use this signature and finding 3's tests.
