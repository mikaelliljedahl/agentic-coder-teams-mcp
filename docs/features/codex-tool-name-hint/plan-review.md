# Independent plan review: Codex tool-name hint

**Verdict: APPROVE WITH CHANGES.** The default Codex spelling and the spawn/resume insertion points are supported by the code. Resolve findings 1–4 before implementation; findings 5–6 should be reflected in tests and documentation.

## Findings

1. **Major — The hint describes downstream replies incorrectly.** The draft says to “read replies with `mcp__win_agent_teams__read_messages`.” For a spawned Codex worker, a lead's `send_message` to that worker uses the guaranteed resume path; it does not enter the worker's inbox (`server_simple.py:3521–3550`; `docs/reference/agent-messaging-protocol.md:254–265, 1777–1791`). `read_messages` reads the caller's own inbox and will not retrieve that reply. **Recommendation:** tell the worker to message its parent with the MCP `send_message` tool and that follow-up work arrives through resume. Mention `read_messages` only for inbox messages that may actually be delivered there. Add an assertion for this wording.

2. **Major — The join prompt still instructs bare `join_team` and `leave_team` calls.** Section 2.3 adds full names only for `external_read`, `external_send`, and (flag on) `external_set_wake`, while `_build_join_prompt` steps 1 and 5 (`server_simple.py:841–851`) remain bare. This misses the plan's stated goal for every injected Codex instruction, especially the first action of an external member. The `join_team` response also repeats bare member-tool instructions (`server_simple.py:938–941`), though that response is outside the listed prompt surfaces. **Recommendation:** name the full Codex and Claude spellings for every tool in the join protocol, at least `join_team`, `external_read`, `external_send`, `leave_team`, and flag-on `external_set_wake`. Keep the literal argument examples. Decide explicitly whether the `join_team` response needs the same guidance, and test the first and last actions as well as polling.

3. **Minor — “Exact model-visible name” assumes more Codex configuration than the plan states.** The supplied Codex 0.156.1 source does confirm the default sanitizer and prefix (`codex-mcp/src/mcp/mod.rs:563–578`, `codex-mcp/src/tools.rs:139–146, 225–233`) and the code-mode flattening (`tools/src/code_mode.rs:184–195`). But Codex also supports `NonPrefixedMcpToolNames` and a per-server `non_prefixed_mcp_tool_names` setting (`core/src/config/mod.rs:857–858, 1837–1840, 3354–3365`), and normalization can add suffixes for namespace/tool collisions (`codex-mcp/src/tools.rs:153–209`). The key can remain `win-agent-teams` and identity can work while the proposed spelling is no longer exact. **Recommendation:** scope the hardcoded spelling and README claim to the standard configuration; document that name-changing Codex options can invalidate the hint, or detect/handle them if exactness under those options is a requirement. Do not claim that a wrong hint implies broken identity.

4. **Minor — The proposed follow-up integration test needs a real Codex command builder.** `tests/test_follow_up_delivery.py` currently installs `_FakeResumeBackend`, whose `resume()` records `SpawnRequest.prompt` and never builds argv (lines 47–79). A test there cannot see the new backend-added hint in `build_resume_command`. **Recommendation:** either add a focused integration test that stubs process launch but invokes `CodexBackend.build_resume_command`, or assert delivery materialization in that file and assert the final argv in `tests/test_backends/test_codex.py`. Establish red on the final argv, including a preserved delivery marker.

5. **Minor — Treat the flag-off golden update as an intentional contract change, not preservation of the old baseline.** `tests/test_native_wake_flag_off.py:46–57` compares the current prompt with a pre-native-wake fixture. The section 2.3 join-prompt line will change that fixture regardless of the flag. Updating only `flag_off.json`'s `prompt` is reasonable, and leaving `tools` alone is correct because no tool docstring changes are planned. However, “flag off ≡ main” does not describe what this golden then tests: it will test the new baseline. **Recommendation:** capture the red golden failure first, update only `prompt`, review the exact diff, and record that the feature intentionally changes the flag-off prompt while flag-on adds only its wake step.

6. **Nit — Tighten the verification and citations.** The Windows hint text itself contains none of the `cmd.exe` metacharacters listed in `_launches_via_cmd_shim` (`codex.py:553–589`); the `\n\n` separator will make even a one-line resume prompt use JSON wrapping through `.cmd`. Test case 4 should decode the *complete* JSON-carried prompt and check one preserved delivery marker as well as the hint; testing the hint string's safety alone does not verify transport. The line cited at `core/src/tools/handlers/mcp.rs:100–117` describes a hook tool name, while `tools/src/code_mode.rs:184–195` directly establishes the code-mode callable name. Also update the README's bare Codex `send_message` walkthrough at `README.md:682–683` when adding the setup note, so the example does not repeat the ambiguity. **Recommendation:** add the argv round-trip assertion, cite the code-mode function for that spelling, and revise the walkthrough.

## Questions and checks

- **Q1 — No server-key override in this change.** Agree. `_MCP_SERVER_NAME` is already used for the identity override (`codex.py:494–524`), and README setup uses that key. Keep one constant. The Codex prefix and collision caveat in finding 3 is separate from the server key.
- **Q2 — Keep the join-prompt guidance.** Agree. A backend-neutral paste prompt cannot infer the receiving client, and the extra line helps Codex external members in both code mode and ordinary tool mode. Expand it as in finding 2. The prompt golden change is justified with the review discipline in finding 5.
- **Q3 — Always append the spawn/resume hint.** Agree. A substring check is an unreliable signal that the caller gave complete, correct guidance, and every resume may contain new instructions. Keep the hint once per constructed prompt.

The cited repo call sites are otherwise accurate: Codex spawn ends in `_correlated_prompt` (`codex.py:394–398`), resume uses `_prompt_arg(request)` (`:429–431`), `_materialize_prompt` adds the delivery marker before the backend (`server_simple.py:2830–2838`), and `codex queue` builds its separate notice (`native_wake.py:589–600`). The default `mcp__win_agent_teams__send_message` spelling is supported by the supplied source and by the observed successful code-mode call. In code mode the callable form is `tools.mcp__win_agent_teams__send_message(...)`; outside code mode the MCP tool is exposed by its namespaced tool call. The draft's plain full name is useful guidance for either mode, subject to finding 3. The proposed smoke is valuable because unit tests cannot prove that a model selects the intended tool on its first turn.
