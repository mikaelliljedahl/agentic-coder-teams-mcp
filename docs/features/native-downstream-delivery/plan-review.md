# Native downstream delivery — plan review

VERDICT: CHANGES_REQUESTED

Reviewed the draft at `07eaf67` against its stated implementation baseline
`471a175`, the messaging protocol, and the native-session-wake plan, reviews,
implementation report and smoke record. Source references below are to
`471a175` unless explicitly identified otherwise. Concurrent implementation
edits appeared in the worktree during review; this is a review of the draft,
not an approval of those edits. No source code was changed by this reviewer.

## Findings

1. [BLOCKER] `docs/features/native-downstream-delivery/plan.md:128-138,317-318` — A persistent Codex queue invalidates the existing dead-process negative-receipt rule. `delivery.py:610-613` fails confirmation when the child dies; `server_simple.py:2614-2634` settles an absent nonce after death/grace; kill settles an absent nonce **before** terminating the process (`:2677-2684,6116-6123`). None proves that a durable queue entry cannot dispatch on a later load. A caller can receive `failed`, retry the instruction under a new key via resume, then execute both the surviving queue entry and the retry. An original nonce attributes the late execution; it does not deduplicate it. **Fix:** define carrier-aware confirmation/reconciliation/kill semantics. Native queue attempts remain unresolved after process death, record removal and reboot until a receipt or authoritative removal/non-enqueue proof exists. Block unsafe resume retries of the same instruction, including a new key; specify whether different messages may resume a thread with unresolved queued work. If queue cancellation cannot be proven, report that limitation instead of terminal failure. Test enqueue → timeout → child death → negative scan → new-key retry → thread reload, and kill → same-name replacement → old queue dispatch.

2. [BLOCKER] `docs/features/native-downstream-delivery/plan.md:169-171,272` — `post_failed` plus an absent transcript nonce is not proof of non-delivery. The current POSIX poster catches exceptions across `sendall` **and** `shutdown` (`native_wake.py:124-128`): the complete user line may already have been accepted when shutdown fails. A Windows cancellation can likewise race successful completion. Transcript persistence can lag behind either event. Moving the row to pending authorizes a duplicate post/resume. **Fix:** return a structured transport outcome distinguishing failure before any user-message write from an attempted/partial/complete write with uncertain acceptance. Once writing begins, preserve `unconfirmed` unless a documented transport acknowledgment proves rejection; absence alone is insufficient. Never retake a `taken` entry after poster death merely because its nonce is absent. Test full acceptance followed by shutdown failure, timeout racing completion, partial writes, delayed transcript flush, and poster crash after acceptance but before `posted` CAS.

3. [BLOCKER] `docs/features/native-downstream-delivery/plan.md:152-153` — Publishing `offered` before `_mark_attempt_sent` reverses the established crash contract (`server_simple.py:4859-4887`). The child may take/post immediately, while the durable row still lacks its nonce and snapshot; a lead crash or failed sent-row write then leaves a delivered instruction looking unsent and eligible for retry. **Fix:** durably persist the attempt, method, nonce, target snapshot and lease identity before exposing it to the poster. Specify recovery for sent-without-offer: use a durable not-yet-actionable mailbox state or an atomic locked publish protocol whose orphan state is provably unsent. Do not infer that a missing mailbox file means no post occurred. Test crashes and failed persistence at every boundary, including mailbox publish succeeding while the subsequent delivery-store write fails.

4. [BLOCKER] `docs/features/native-downstream-delivery/plan.md:114-119,168-169,181-183` — Putting the receipt marker in the wrapper changes the prompt-file lifetime contract. Existing finalization and reconciliation delete the file on receipt (`server_simple.py:4361-4362,2610-2612`), whereas the current Claude sidecar receipt comes from the file's `tool_result` (`delivery.py:198-218`; protocol `:1205,1353-1375`). Under this plan the wrapper can be recorded before the agent opens the file, so confirmation deletes its task body. Codex currently has no sidecar transport (`server_simple.py:2827-2838`), so this is a new lifecycle, not reuse of an existing Codex one. **Fix:** keep native sidecars pinned after wrapper delivery until a separate file-read acknowledgment or explicit safe release; exclude unresolved durable carriers from age GC and process-death cleanup as well. Define the public meaning of `delivered` for wrappers. Test wrapper receipt → immediate reconciliation → delayed file read, plus queue persistence across reboot/GC and kill.

5. [MAJOR] `docs/features/native-downstream-delivery/plan.md:154-157,266-268` — The retract-versus-take rule is described as a preliminary state check followed by retract, without defining the authoritative result. If the lead reads `offered`, the poster takes it, and retract loses, returning pending still permits a second attempt. A retract write failure or corrupt mailbox creates the same problem. **Fix:** have one locked CAS return `retracted`, `already_taken/posted`, or `unknown/error`; only a **durably successful** offered→retracted transition permits pending/new nonce. Preserve uncertainty for contention, lost writes and malformed state. Fail closed on unreadable/non-object mailbox data, following `delivery_store.py:263-300` and `leases.py:load_leases`. Add deterministic barrier tests for both race winners, CAS persistence failure, and corruption rather than relying only on stress.

6. [MAJOR] `docs/features/native-downstream-delivery/plan.md:145-165,135-138,274-275` — Neither entries nor capability markers identify the target host incarnation/bound transcript, and the poster has no specified lease/generation fence. A lifetime lock proves that *some* server holds a lock; a fresh heartbeat does not prove it is the server for the current child. After holder death, force-clear, resume or name reuse, a surviving/restarted poster can consume an old offer into a different host. Finalization's generation/operation CAS (`server_simple.py:4252-4275`) cannot undo a socket post already made. **Fix:** bind entries and capabilities to session, identity, correlation/incarnation, backend session, host PID/create token, operation and generation. Validate those bindings at take and immediately before post; distinguish delivery generations from stable host incarnation. Define a global lock order and a kill/force protocol that fences offers, retracts offered work, and treats already-taken work conservatively before settlement/removal. Include the CLI force path (`leases.py:force_clear_lease`) and cleanup in the affected files. Test lead death while child poster survives, force racing take/post, host resume, and same-name successor at a reused numeric generation.

7. [MAJOR] `docs/features/native-downstream-delivery/plan.md:166-174,269-270` — A missing marker is explicitly allowed although it supplies no idle proof. Also a `waiting` observation is not an atomic idle edge: a user/native notice can start a turn after the check, or socket input may not trigger the expected running hook promptly. Thus “never lands between tool calls” does not follow from this loop. Edge-only posting can also strand a second entry after a first post is held/dropped and no running→waiting edge occurs. **Fix:** require a current, incarnation-bound affirmative idle marker; define what resets/rearms the edge and what happens when an accepted write starts no turn. Verify real socket input hook ordering and races with manual input/ordinary native wake. If the host offers no atomic idle-only enqueue, document the remaining timing limitation instead of promising it cannot post mid-turn. Test no/stale marker, waiting→running between take and post, accepted-but-refused input, MCP restart while waiting, and two consecutive offers.

8. [MAJOR] `docs/features/native-downstream-delivery/plan.md:80-102,104-105,129` — End-of-prepare selection is too late to implement the stated busy and `replace_if_idle=False` behavior. Current `_prepare` returns before reserving a lease for busy or idle-but-not-replaceable agents (`server_simple.py:4567-4624`). A native pre-enqueue failure discovered after bypassing that gate must not immediately kill a still-busy target via fallback. **Fix:** specify two stages: determine provisional native eligibility before the idle/replacement gate, then revalidate and commit the method under the granted lease. Safe fallback must re-enter the existing idle/replace checks within the original call budget and release/transfer its lease and FIFO ticket explicitly; never call resume directly from a native error branch. Test busy→native failure→still busy, eligibility disappearing while waiting for a lease, `replace_if_idle=False` with native success/failure, and original-budget exhaustion.

9. [MAJOR] `docs/features/native-downstream-delivery/plan.md:209-224,281-283` — F3 omits several requirements already resolved in the predecessor review. The current notifier starts only under the Claude half/platform gate (`server_simple.py:7149-7155`) and exits when the Claude channel is unavailable or `_CLAUDE=0` (`native_wake.py:343-368`). Merely adding a channel kind will not wake a Windows Codex lead or a Codex-only installation. Registration also lacks locking, monotonic clear tombstones, generation-keyed notice/backoff/cache state, revalidation and activation/restart rules. **Fix:** start a notifier when either eligible host channel is enabled and gate each channel independently. Carry forward predecessor R2-B/R3-A/R3-C: generation-preserving clear, synchronized registration snapshots, per-registration notice/cache/backoff state, pre-queue target/generation checks and transition-only catch-up. Specify how automatic registration waits for late binding and how it stops/replaces on host incarnation changes; a startup-only check is insufficient. Test `_CLAUDE=0/_CODEX=1`, Windows Codex, undrained A→B, clear→set, backoff→replacement, delayed binding, restart backlog and a session switch during queue. Do not replace the existing external-member `external_read` notice with the lead's `read_messages` notice when extracting the runner.

10. [MAJOR] `docs/features/native-downstream-delivery/plan.md:175-180,215-218,243-244` — Repeating flags in Claude `build_env` does not solve an MCP environment filter, and does not address spawned Codex F3 at all. Process launchers already merge the parent's environment (`process_manager.py:636-637,1096-1097,1499-1500`); the observed missing MCP flag happened despite ordinary process inheritance. The explicit Claude MCP config contains only identity/launcher variables (`server_simple.py:2704-2723`), and Codex separately constructs MCP identity configuration. **Fix:** after S-2, propagate effective master, downstream and **both half-switch values** through the child MCP configuration/overrides as well as the host process where needed; include Codex nested leads. Do not blindly turn downstream on just because master wake is on, or drop an explicit half disable. Preserve the socket/token scrub in `process_base.py:104-108`. Test generated MCP env on spawn and resume, master-only/downstream-only combinations, `_CLAUDE=0`/`_CODEX=0`, nested Codex leads and a real child's MCP environment. Missing capability may make B safe, but silently making B/F3 unusable does not complete the feature.

11. [MAJOR] `docs/features/native-downstream-delivery/plan.md:195-202,276-279,320` — Cancel-and-drain protects memory lifetime, but does not by itself establish a hard operation deadline. `CancelIoEx` requests cancellation; `GetOverlappedResult(wait=True)` can still wait past the deadline. Cancellation can also lose to a successful write. The plan must retain the buffer, `OVERLAPPED`, event and pipe handle through **all** completion/error paths, including cancellation failure, not just the expected timeout path. **Fix:** define a bounded caller policy separately from completion cleanup. Keep any outstanding operation in a bounded owned object until drained, disable/back off the affected target, and never free its storage or retry its delivery on uncertainty; alternatively retain Windows unsupported until tested cancellation bounds justify the supported guarantee. Specify ctypes signatures/handle widths, immediate `WriteFile` success versus `ERROR_IO_PENDING`, wait failure, completion byte count, `ERROR_NOT_FOUND` cancellation races and event cleanup. Never pass rounded-down zero to `WaitNamedPipeW` after budget expiry (zero means the server's default timeout); retry busy opens only inside the remaining monotonic budget. Test cancellation failure/delayed completion, immediate completion, cancel→success, short write and 64-bit handles. See Microsoft's [CancelIoEx](https://learn.microsoft.com/en-us/windows/win32/api/ioapiset/nf-ioapiset-cancelioex), [cancellation guidance](https://learn.microsoft.com/en-us/windows/win32/fileio/canceling-pending-i-o-operations), and [WaitNamedPipeW](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-waitnamedpipew).

12. [MINOR] `docs/features/native-downstream-delivery/plan.md:189-194,297-298` — Server PID equality is a useful fail-closed gate, but the draft states it as an established ownership fact before S-4 proves the real host/pipe arrangement. A Desktop broker or Node-hosted CLI may differ from the expected `claude.exe`, and a cached path check cannot verify a subsequently reopened pipe instance. **Fix:** check successful `GetNamedPipeServerProcessId` on the **same handle used to write**, before auth/token bytes, and fail closed on query failure as well as mismatch. Keep Windows unavailable when CLI/Desktop S-4 cannot prove the supported host mapping; avoid widening to arbitrary ancestors to make it pass. Verify the client-opened handle experimentally (the Microsoft [API page](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid) describes a CreateNamedPipe-created handle), and add query-failure, pipe replacement and CLI/Desktop host tests.

13. [MINOR] `docs/features/native-downstream-delivery/plan.md:112-122` — The helper does not preserve the current runner's cwd: `CodexMemberWake._queue` uses `Path.home()` (`native_wake.py:624`), not the reported `CODEX_HOME`. The predecessor explicitly fixed this difference (review R2-E; implementation “member-supplied home”). Also a character count does not bound UTF-8 argv bytes on POSIX or quoted UTF-16 command-line units on Windows. **Fix:** keep `CODEX_HOME=home` and `cwd=Path.home()`, calculate the platform budget from the complete encoded/quoted command, and use a sidecar when it is exceeded. Add quote-heavy, non-BMP, long-path and multibyte cases. Discovery/spawn failures that prove no subprocess started may safely fall back; classify them separately from ambiguous execution failures.

14. [NIT] `docs/features/native-downstream-delivery/plan.md:47-51,98-100,253-254` — Most baseline citations are accurate, but the child shutdown is graceful first with a conditional force kill (`server_simple.py:4761-4766`), not an unconditional force kill; `delivery.py:162-195` identifies receipt extractors, while actual confirmation is `:572-616`. The busy verification cross-reference says §5 N3 (Claude idle), but means N2. “Flag-off golden” also leaves master-on/downstream-off compatibility ambiguous, since C/D are intentionally active there. **Fix:** correct these references/wording and spell out separate baseline expectations for master off, master on/downstream off, and half-disabled channels. Preserve missing `method` on flag-off public views even for previously persisted native rows (`delivery_store.py:232-260`).

## Answers to §8

1. **Treat every subprocess non-zero exit as unconfirmed by default.** Stderr is not an enqueue receipt. Permit fallback for local validation/discovery/exec failure proving no child started. Add a CLI pre-enqueue allowlist only after auditing and pinning supported Codex source/version paths; unknown versions/messages remain uncertain. Test “enqueue succeeded, then CLI exits non-zero.”
2. **Use one JSON document and one stable lock initially.** It makes take/retract CAS and ordering easiest to inspect. Add strict validation, fail-closed reads/writes, bounded terminal-entry retention and recovery rules. One file per entry still requires locking/CAS and complicates enumeration and cleanup; adopt it only if measured mailbox volume requires it.
3. **Keep affirmative-idle-only posting for this feature.** Do not add a mid-turn sender option. Remove the missing-marker exemption, verify native-input marker transitions, and state any unavoidable observation-to-post race honestly (finding 7).
4. **Require child confirmation through its host-provided `CODEX_THREAD_ID` and effective `CODEX_HOME`.** Match them to the parent's positively bound record, verify the thread, and tie registration to host incarnation. Parent binding is valuable corroboration, but does not prove this particular MCP server belongs to that thread. If the MCP environment filters the thread id, retain explicit registration/manual fallback instead of guessing.
