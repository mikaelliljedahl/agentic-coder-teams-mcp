CHANGES REQUIRED

Independent Codex plan review, 2026-09-25. Reviewed `plan.md`, `CLAUDE.md`, and commit `c72a378` against its parent/origin/main `e5c8e98`. Findings concern the proposed design; implementation references demonstrate the consequences. No implementation files were changed.

1. **BLOCKER — The sidecar and repeat-signal design breaks fail-closed ownership.** `docs/features/macos-process-liveness/plan.md:65-68` promises never to signal an unproven PID, but `src/claude_teams/server_simple.py:5838-5839` proves only the launcher; lines 5870-5878 resolve and kill the sidecar, and lines 5912-5913 re-signal on bare liveness. `src/claude_teams/backends/process_manager.py:2100-2105` explicitly warns that sidecar PIDs can be reused; the resolver at lines 2116-2125 supplies no identity proof. The original launcher can also exit and have its PID reused during the first kill, before the verification tail. A read-only, stubbed execution of the actual extracted helpers produced ownership probes `['4242']` and kill calls `['4242', '4242', '9999']`: 9999 was never proven. **Fix:** make verification observation-only; never authorize a second signal from an earlier ownership decision. If sidecar termination stays in scope, persist its creation token at trusted launch time and validate it immediately before signalling; absent proof, report an unverified candidate without signalling. Do not manufacture an expected token by reading an arbitrary stale sidecar PID at kill time. Audit the existing tracked Linux-terminal kill path at `process_manager.py:2133-2138` too, since it independently signals the same bare sidecar. Add stale-sidecar and PID-reuse-between-initial-kill-and-verification tests asserting zero signals to the foreign identity. Numeric PID checks still have a residual check/signal race; describe that limitation rather than asserting atomic identity safety.

2. **BLOCKER — Observation failure is treated as confirmed death on all three platforms.** The plan at `plan.md:45` and the helper docstring promise absence semantics, but `process_manager.py:308-321` returns the same `None` for load failure, either sysctl error, a short reply, and disappearance; lines 410-412 turn all of them into dead. Linux lines 415-418 likewise treat EPERM as death. Windows lines 436-437 use creation-token readability as liveness although lines 213-219 explicitly say unreadable tokens include access denial. This regresses the existing Windows liveness policy at lines 1066-1073, which treats denied/failed queries conservatively. Consequently `wait_pid_exit` can return true and `server_simple.py:5880-5881` claim termination without observing exit. An injected CDLL failure against the review process reproduced `pid_alive(self) == False`. **Fix:** distinguish gone/zombie, alive, and unknown, or conservatively keep unknown alive for verification; only confirmed absence/exit may satisfy the wait. Preserve EPERM as alive on POSIX, use exit-aware Windows checks, and keep token-read failure separate from process death. Add injected first/second sysctl failures, short replies, Linux EPERM/ESRCH, and Windows denied/query-failure/exited-process cases. Unknown must not authorize signalling or immediate prompt deletion.

3. **SHOULD — Move the new verification wait outside the session-wide transaction.** `plan.md:91-95` accepts about 20 seconds under the registry lock. `_agents_transaction` holds the cross-process lock across its yield (`server_simple.py:613-616`), including termination at line 6025 and cleanup through line 6038. This stalls unrelated agents in the session. Twenty seconds is not an overall bound: manager termination can already wait before the new tail (`process_manager.py:959-965`, `2133-2147`), and Windows lock acquisition times out after 30 seconds (`src/claude_teams/filelock.py:31-32`). **Minimal fix:** split termination initiation from observation. Under the existing transaction, perform the ownership-gated initial action, save the removed row, drop its lease, and perform conservative artifact cleanup; capture immutable process identities. Release the transaction before the new observation-only wait and construct the result afterward. Do not later delete name-keyed artifacts outside the lock: a successor may already own them. Keeping prompt files until age-based GC when exit is not yet confirmed is safer than adding a new race. Existing manager waits remain a documented residual; moving all termination outside the lock would instead require an explicit per-agent termination reservation. Add a deterministic blocked-verifier test proving another agent can load/update the registry and a same-name replacement retains its files.

4. **SHOULD — The offsets are correct, but decode the actual timeval ABI and strengthen its tests.** `plan.md:88-90` is correct about starttime offset 0 and state offset 36 on little-endian LP64 arm64/x86_64: a 16-byte union, two 8-byte pointers, and a 4-byte flag precede the state byte. A 64-byte minimum safely covers these reads, but is merely a prefix bound, not proof of a complete/recognized kinfo_proc layout. `process_manager.py:323` uses `<qq`; Darwin's timeval has a 64-bit seconds field and a **32-bit** microseconds field, followed by padding. Current XNU zeroes the output structure, explaining why this works today, but the parser unnecessarily incorporates padding. **Fix:** use `<qi` (or a correctly declared ctypes prefix), validate `0 <= usec < 1000000`, declare sysctl argument/result types, and document the supported 64-bit ABI. Add Linux-runnable synthetic replies with nonzero padding, zero/short lengths, valid states, and distinct start times; live token stability alone (`tests/test_process_liveness.py:43-55`) does not prove the field is correct. Compare an actual macOS child start time against an independent measurement and retain arm64/x86_64 validation evidence. Primary sources: [Apple user64_extern_proc](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/proc_internal.h#L638-L650), [Apple user64_timeval](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/_types/_user64_timeval.h#L30-L34), and [XNU output initialization](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_sysctl.c#L775-L781).

5. **SHOULD — A dead launcher still hides a surviving agent.** `server_simple.py:5840-5842` returns `process_already_dead` before resolving the sidecar at line 5870. The existing `_agent_alive` rationale at lines 1738-1742 explicitly recognizes that the agent can outlive its launcher. Thus the plan's launcher recovery (`plan.md:66-70`) misses an important orphan case and reports no orphan candidate when the launcher is gone. **Fix:** inspect a distinct sidecar candidate for reporting even when the launcher cannot be proven alive; keep its unproven identity separate from permission to signal (finding 1). Describe whether “dead” means the recorded launcher or every identified agent process. Test dead launcher/live sidecar, unowned launcher/live sidecar, and both dead; do not claim the whole agent is gone from the launcher alone.

6. **SHOULD — Complete the tool-visible return contract and avoid unsafe remediation advice.** `plan.md:73-74` is not satisfied by `server_simple.py:5930-5942`: the docstring omits the ordinary reason enumeration and tells every caller to check a field that is absent on early failures (`5947-5952`, `5988-6014`). It also suggests every false outcome with a live process has orphan details, despite the deliberately unprobed external-agent exception. `docs/reference/agent-messaging-protocol.md:516-531` contains more of the contract, but consumers only read tool descriptions (`CLAUDE.md:72-74`). The automatic “Kill it by hand” advice at `server_simple.py:5859-5863` is especially wrong for a token mismatch: that PID may belong to an unrelated process, not an orphan. **Fix:** document success-first branching, optional fields on failures, all termination reasons, already-dead versus killed, external deregistration, and the bounded verification wait in the tool docstring. For unproven PIDs say “identity unverified; inspect ownership before any manual termination,” rather than directly instructing a kill. Remove the claim that a PID result measures reclaimed memory; no RSS/process-tree measurement is performed. Keep the protocol and docstring aligned and test the response shapes, including missing agent and live-lease refusal.

7. **SHOULD — The zombie test can skip precisely when it should detect a regression.** `tests/test_process_liveness.py:82` invokes `child.poll()`, which reaps an exited child; line 86 then skips. If zombie exclusion is broken, the loop can keep seeing alive until its own poll reaps the zombie and skip instead of fail. **Fix:** do not poll/wait during the observation phase. Wait for independently observed zombie status (or waitid with WNOWAIT where supported), assert public liveness is false while the child remains unreaped, and reap only in fixture cleanup; timeout must fail. Linux's `rsplit(') ', 1)`/`Z ` parsing at `process_manager.py:399-400` is appropriate for comm fields containing parentheses, but add deterministic parser cases for those names and missing/denied stat reads. The module helper is new; this change does not unify all managers' existing `_pid_alive` methods. Also cover two surviving handles, deduplication of identical handles, real timeout boundaries, and the ownership/error/concurrency cases above: the current kill mocks substitute the verification result (`tests/test_kill_agent.py:78-80`), so they cannot establish those properties.

8. **SHOULD — Correct the platform validation plan and distinguish evidence from intended gates.** `plan.md:99-100` says CI is Linux-only, but `.github/workflows/ci.yml:36-50` has a Windows pytest job. Linux runs lint/type/test; Windows runs tests; neither validates native Darwin. `plan.md:14` also calls the Windows token reader WMI, while `process_manager.py:213-251` uses GetProcessTimes. **Fix:** update those facts, require both existing CI jobs, add portable mocked Darwin ABI/error tests to Linux CI, and record native macOS results with OS/architecture. Preserve the separate procinfo scope (`plan.md:20-23`) but explicitly disposition its known failure and report the full suite as red if it remains red, as required by `CLAUDE.md:36-41`. Do not label this plan review as post-implementation approval or recreate historical red/green evidence: the retrospective status at `plan.md:5-9` should remain explicit.

9. **NIT — Remove consuming-project residue from the upstream diff.** The stale reference appears in **two** places: `server_simple.py:5829` and `tests/test_kill_agent.py:165`, not just one comment as `plan.md:101-102` implies. `process_manager.py:40-44` also describes a discarded libproc/PROC_PIDTBSDINFO approach immediately above sysctl constants. **Fix:** remove both nonexistent CLAUDE.md section references, replace the obsolete libproc comment with the actual sysctl ABI rationale, and omit unmeasured application-specific memory sizes from the public contract. Keep the useful failure description without importing a consuming project's policy.

Resolve those before approval; shorten the lock scope and complete the tool contract and regression coverage.
