1. **BLOCKER — The no-match control flow does not create the repo workspace when any active workspace already exists.** The plan defines `None` as “create one” (`docs/features/herdr-workspace-per-repo/plan.md:73-75`), but its pseudocode still runs an unqualified `tab create` first (`docs/features/herdr-workspace-per-repo/plan.md:83-91`). Per the contract recorded in the plan, an unqualified create goes to the active workspace; the current implementation relies on exactly that behavior (`src/claude_teams/backends/process_manager.py:3023-3038`). Therefore, if repo B has no matching workspace while repo A is active, repo B's tab creation succeeds in repo A and the fallback is never reached. Proposed test 6 encodes the same faulty assumption by expecting “no `--workspace`” to lead to `workspace create` (`docs/features/herdr-workspace-per-repo/plan.md:133-134`). A valid empty/no-match result must lead directly to `workspace create` (subject to race handling below), while a deliberate legacy/degraded path may issue an unqualified `tab create`. Add a test with an unrelated active workspace where unqualified `tab create` would succeed; the expected call must instead be repo-labelled `workspace create`.

2. **BLOCKER — The plan has no serialization or retry strategy for parallel spawns, so it cannot guarantee one workspace per repo.** Two processes can both list, observe no match, and both create a workspace; Herdr explicitly permits duplicate labels (`docs/features/herdr-workspace-per-repo/plan.md:42-44`). Selecting the lowest number only makes later spawns converge and does not prevent the two initial agents from landing in different workspaces. The existing `file_lock` protects only server discovery/startup and is released before `_create_tab` runs (`src/claude_teams/backends/process_manager.py:2547-2553`, `src/claude_teams/backends/process_manager.py:2713-2716`). The plan needs a session/config-scoped, cross-process critical section covering re-list plus create (and the stale-ID recovery path should re-list under that lock before creating). It also needs a barrier-based concurrent test demonstrating that two simultaneous no-match spawns create at most one workspace and both ultimately target it.

3. **SHOULD — Workspace-list failure and a valid “no match” are incorrectly collapsed into one state, and the error-code policy is too broad.** The plan says `HerdrCommandError` and malformed data both return `None`, yet calls that “create one” and also says this degrades to today's active-workspace behavior (`docs/features/herdr-workspace-per-repo/plan.md:66-75`); those are different actions with different side effects. In the real boundary, `cli_usage`, nonzero exit, timeout/unavailable, and malformed protocol responses are deliberately distinguishable (`src/claude_teams/backends/process_manager.py:2438-2454`, `src/claude_teams/backends/process_manager.py:2505-2531`). Silently treating all of them as absence can either misroute an agent or create duplicate workspaces during a transient failure. Define at least three outcomes—match, authoritative no-match, and indeterminate—and state which errors fail the spawn versus intentionally use legacy active routing. Tests should cover `cli_usage`, malformed payload, timeout/unavailable, and a non-workspace error from targeted `tab create`, not only a generic list exception and `workspace_not_found` (`docs/features/herdr-workspace-per-repo/plan.md:135-137`).

4. **SHOULD — Rollback and workspace ownership are underspecified for the new direct-create path.** Spawn rollback starts only after `_create_tab` returns and currently closes a tab id extracted from the response (`src/claude_teams/backends/process_manager.py:2716-2739`, `src/claude_teams/backends/process_manager.py:3087-3117`). A newly created workspace is a resource created by this spawn, unlike a reused matching workspace. The plan should state and test what happens if `workspace create` succeeds and then pane validation, `pane run`, PID lookup, token lookup, or provenance writing fails: whether closing its root tab removes the workspace under Herdr's contract, or whether the code must retain the created workspace id and explicitly close only a workspace it created. “Workspace cleanup when the last agent exits” being out of scope (`docs/features/herdr-workspace-per-repo/plan.md:10-11`) does not cover rollback of a failed spawn. Existing rollback tests exercise a `tab_created` response (`tests/test_backends/test_process_manager_herdr.py:1554-1576`, `tests/test_backends/test_process_manager_herdr.py:1579-1605`), not `workspace_created`.

5. **SHOULD — The test plan does not account for the existing spawn harness or verify the workspace id that lifecycle code actually stores.** Every ordinary `_Herdr`-backed spawn currently has replies only for `tab_created`, `pane_process_info`, and `ok` (`tests/test_backends/test_process_manager_herdr.py:297-314`); adding an unconditional `workspace list` will make many existing tests fail with a fixture `KeyError` unless the harness is deliberately adapted. More importantly, the manager records `root_pane.workspace_id` in `HerdrProcessInfo` (`src/claude_teams/backends/process_manager.py:2741-2755`) and later ownership probes address the workspace-qualified pane id (`src/claude_teams/backends/process_manager.py:2758-2790`), but proposed test 4 checks only argv and the existing assertion uses a fixed unrelated `w3` fixture (`tests/test_backends/test_process_manager_herdr.py:358-371`). Add end-to-end unit cases for both reuse and creation that return the selected/created workspace id, assert it is stored, and assert rollback closes the returned tab rather than a tab in the previously active workspace.

6. **SHOULD — The override validation is inconsistent with the label semantics and overstates an argv-injection risk.** The plan allows labels derived from arbitrary folder names, but proposes validating an explicit label with the session-name-style guard (`docs/features/herdr-workspace-per-repo/plan.md:101-106`). `_HERDR_SESSION_RE` is intentionally narrow because session names are both a path component and a top-level selector (`src/claude_teams/backends/process_manager.py:62-66`, `src/claude_teams/backends/process_manager.py:2376-2388`); workspace labels are values supplied after `--label`, and Herdr's CLI contract calls that argument free-form text. Reusing the session language would reject ordinary matching labels such as `repo.name` or labels with spaces even though automatic derivation and human-created workspaces may use them. Specify label-appropriate validation/length rules and tests, including a label that is valid for Herdr but invalid as a session name. If leading-dash handling is a parser concern, use an unambiguous CLI form or explicitly test it; separate argv tokens cannot “smuggle argv” in the shell-injection sense.

7. **SHOULD — Workspace-list parsing and deterministic selection need explicit validation rules and adversarial tests.** `_run_herdr` validates only the envelope and result `type`, not the contents of `workspaces` (`src/claude_teams/backends/process_manager.py:2495-2532`). The plan promises malformed listings become no match (`docs/features/herdr-workspace-per-repo/plan.md:68-75`) but does not define behavior for a non-list `workspaces`, non-object entries, missing/empty `workspace_id`, non-integer or boolean `number`, or equal numbers. Sorting raw mixed JSON values can itself raise `TypeError`. Require a nonempty string id and a well-defined numeric ordering, add an id tie-breaker if Herdr does not guarantee unique numbers, and test malformed/mixed entries so resolution remains bounded and deterministic.

8. **SHOULD — Label derivation tests do not fully cover the failure contract the design promises.** The implementation is supposed to swallow timeout, empty output, undecodable output, nonzero exit, and missing Git (`docs/features/herdr-workspace-per-repo/plan.md:52-62`), but proposed test 2 only names generic Git failure/absence (`docs/features/herdr-workspace-per-repo/plan.md:128-130`). Add explicit timeout and empty/whitespace-output cases, root/empty-basename fallback, and normal-repository versus bare-repository shapes. Also make the algorithm explicit: for a normal/common dir ending in `.git`, use the parent checkout basename; for a bare common dir, use that directory's basename and strip only its terminal `.git`. The phrase “its parent's basename” followed by the bare special case is otherwise easy to implement incorrectly.

9. **NIT — The documentation and provenance changes should be concrete.** README does describe the Herdr launcher and settings (`README.md:272-298`), while `docs/reference/agent-messaging-protocol.md` does not currently describe launcher behavior, so the conditional file list at `docs/features/herdr-workspace-per-repo/plan.md:108-114` should name README as required and omit the unrelated protocol document unless a specific section is identified. Since provenance currently logs session/tab/pane/PID but not the stored workspace id (`src/claude_teams/backends/process_manager.py:3098-3106`), including the workspace id/label would also make misrouting and duplicate-workspace failures diagnosable.

Overall verdict: **CHANGES REQUESTED**
